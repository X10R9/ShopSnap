为什么做它

存图这件事，不该这么费劲

做商品上架、素材归档时，最耗时的往往不是选图，而是把图一张张弄下来：截图会被压缩，右键另存要点几十次，有些图还藏在懒加载里，根本点不到。

这个扩展把流程压成三步：在详情页点一下，在新页面里挑一挑，剩下的交给批量下载。

  • 3个主流平台一键适配
  • 1次点击完成提取
  • 0张图片离开本机

核心功能

六个动作，覆盖存图全流程

从识别页面上的图片，到按你的习惯命名保存，中间不需要切换工具。

多来源提取

不只看 img 标签：懒加载属性、srcset、CSS 背景图、页面内联数据都会扫，没滚动到的图也能找到。

还原原图地址

识别淘宝 _400x400、_q90、_.webp，京东 /n1/，拼多多 imageView2 等缩略参数并去掉，尽量拿到最大版本。

自动分类排序

按主图、SKU 图、详情长图打标，并按来源排好序，打开就是能直接用的顺序。

集中勾选

网格预览支持全选、反选、按来源和尺寸筛选、按尺寸排序，点开还能看大图。

批量转 PNG

统一重新编码为 PNG 并保留透明背景，并发下载，失败的单张可以重试。

不打扰页面

悬浮按钮放在 Shadow DOM 里，不改站点 DOM、不覆盖页面样式，离开详情页自动收起。

使用流程

三步，从详情页到本地文件夹

不需要整理链接，也不用一张张另存为，全程留在浏览器里。

  1. 获取图片
    01

    在详情页点击「获取图片」

    按钮固定在页面右下角，只在商品详情页出现。点击后扩展会自动滚动页面，把懒加载的图都触发出来。

  2. 02

    在新页面里勾选需要的图

    主图默认已选，SKU 图和详情长图按来源分好，用筛选和排序把不要的小图去掉。

  3. PNG PNG PNG
    03

    批量下载为 PNG

    文件按「站点_标题_序号_宽x高」命名，统一存进下载目录的「电商图片」文件夹。

安装步骤

三分钟装好，只用装一次

扩展还在本地加载阶段，没有上架商店，按下面三步手动安装即可。

  1. 01

    打开扩展管理页

    在 Edge 地址栏输入下面的地址并回车，然后打开页面上的「开发人员模式」。

    edge://extensions/
  2. 02

    加载扩展目录

    点击「加载解压缩的扩展」，选中包含 manifest.json 的文件夹，例如本项目里的 day5。

  3. 03

    刷新商品详情页

    回到淘宝、京东或拼多多的商品页刷新一次，右下角出现「获取图片」按钮就说明装好了。

两个容易踩的小坑

  • 改过扩展代码后，要在扩展页点一次「重新加载」，否则加载的仍是旧版本。
  • 已经打开的详情页不会自动获得新按钮，刷新一次即可。

装好之后不用再管它，打开支持的站点会自动生效。

常见问题

你可能还想知道

关于数据、兼容性和使用限制，这里一次说清楚。

是否会上传我的图片或浏览数据？

不会。图片提取、地址还原和 PNG 转换都在你的浏览器本地完成。扩展不包含上传接口、统计脚本或远程代码；提取结果只保存在本次浏览器会话中，浏览器关闭即清除，不会写入磁盘。

支持哪些网站？

目前适配淘宝 / 天猫、京东、拼多多和拼多多商家版。其他网站不会出现按钮，也不会注入任何脚本。站点改版可能导致提取规则失效，届时需要更新扩展。

为什么有时提取到的图片偏少？

多数是懒加载导致的：图片要滚动到可视区域才开始加载。可以先把详情页手动滚到底部，再点「获取图片」。如果滚动后仍然偏少，通常是站点改版让选择器失效了。

下载的图片可以直接商用吗？

工具只负责提取，图片版权归原权利人所有。二次上架或商用前，请确认你拥有相应授权，并遵守平台规则。扩展不会绕过任何登录或访问限制。

为什么动图只保存了一帧？

GIF 和动态 WebP 经过画布转换成 PNG 后只能保留首帧，这是 PNG 格式和浏览器画布的限制，不是提取失败。需要完整动图时，请保留原始文件。

为什么有的图不是 PNG？

超过浏览器画布上限的超大图（约 2.68 亿像素）会降级保存为原格式，避免转换中途失败。除此之外的图片都会统一转成 PNG。

拼多多商家版点击后没反应？

需要先登录商家后台，并进入具体的商品详情页；列表页、报表页不会出现按钮。另外商家后台改版较频繁，如果按钮出现但提取为空，通常是选择器需要更新。
